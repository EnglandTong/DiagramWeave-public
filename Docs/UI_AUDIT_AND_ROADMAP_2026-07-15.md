# DiagramWeave UI 审查与产品升级路线

日期：2026-07-15

## 1. 审查范围

本次审查覆盖：

- 首次进入与空白项目启动
- 主编辑器的信息架构、画布、图形库、属性面板与工具栏
- 模板选择与模板应用
- 节点属性编辑
- 移动端重排
- 键盘与辅助技术可达性
- 现有功能规划与同类产品能力对照

本次没有修改产品代码。截图证据保存在 `audit-results/`。

## 2. 总体判断

DiagramWeave 已经具备一套有价值的本地流程图工作台能力：多页面、多图层、Excel/JSON 工作档、自动布局、关键路径统计、演示模式、Visio 风格连线和扩展内核。这些能力比普通白板更偏向“可分析、可交换、可演示的流程工程工具”。

当前最紧急的问题不是功能数量，而是主题样式失效和工作流组织：

1. CSS 文件开头缺少 `@font-face {`，导致 `:root` Design Token 规则没有被浏览器解析；所有依赖 CSS 变量的颜色和背景均失效。
2. 模板生成后节点为深色填充，但文字仍为黑色，核心流程内容无法可靠阅读。
3. 页面没有响应式断点；390px 视口的文档宽度达到 1074px，画布被左右面板挤出首屏。
4. 主要工具、模板和图形库缺少可访问名称、键盘入口、焦点管理和对话框语义。
5. 强功能散落在顶部图标、左右面板和隐藏表格中，缺少搜索、命令入口、导航概览和流程质量检查。

建议先恢复视觉基础和可用性，再继续扩展功能。否则新增模板、版本历史和 Visio 支持会建立在不稳定的主界面上。

## 3. 流程步骤与健康度

### Step 1：首次进入与项目选择

健康度：需改进

- 优点：明确给出“保存新档案 / 打开旧档案 / 暂不处理”三条路径，符合本地优先定位。
- 问题：首次进入就出现阻断式弹窗，用户尚未看到产品价值，也不清楚三种选择对自动保存的影响。
- 建议：改为欢迎面板，提供“从模板开始 / 导入文件 / 空白画布”三个主入口；文件保存设置放到第一次实际修改后提示。

证据：`audit-results/01-editor-initial.png`

### Step 2：空白画布与工具发现

健康度：较差

- 优点：左图形库、中央画布、右属性栏的专业编辑器结构清晰。
- 问题：空白画布没有下一步引导；顶部大量无文字图标、左侧大量图形与右侧统计同时出现，首次使用认知负担高。
- 建议：空白态加入三个可执行入口；图形库增加搜索、折叠分类、最近使用和收藏；低频命令收入“更多”菜单或命令面板。

证据：`audit-results/02-editor-workspace.png`

### Step 3：模板选择

健康度：基础可用

- 优点：已有 7 个可编辑模板，并覆盖审批回路、泳道、鱼骨、事件响应和发布流水线等实际场景。
- 问题：模板只有文本和小图标，没有画布缩略图、分类、搜索、标签、收藏和预计规模；模板项是可点击 `div`，不能通过键盘正常操作。
- 建议：按现有 `DW-P2-01` 工作单升级为完整模板中心，并将模板项改为语义化按钮或链接。

证据：`audit-results/03-template-center.png`

### Step 4：模板生成与画布阅读

健康度：阻断

- 优点：模板一键应用、自动连线和右侧关键路径统计均已生效。
- 问题：主题变量失效后，节点深色填充与黑色文本叠加，标签几乎不可读；画布网格、面板背景、边界和状态色也同时失效。
- 建议：作为 P0 修复 CSS 解析问题，并增加浏览器级主题、对比度和模板截图回归测试。

证据：`audit-results/04-template-applied.png`

### Step 5：节点属性编辑

健康度：功能丰富但组织偏重

- 优点：编号、下游连接、简介、角色、图形、详细说明、耗时、图层和颜色均可直接编辑。
- 问题：字段平铺且缺少分组折叠、批量编辑和上下文快捷栏；颜色只有无名称色块，辅助技术无法理解颜色含义。
- 建议：分为“内容 / 流程 / 外观 / 数据”四组；选中节点后显示轻量浮动工具栏；多选时提供批量修改。

截图捕获时透明背景渲染异常，未将该截图作为视觉证据；结构结论来自当前 DOM 和源码。

### Step 6：移动端

健康度：不可用

- 390x844 视口下，页面实际宽度为 1074px。
- 左侧图形库与右侧属性栏同时保留固定宽度，中央画布被完全挤出首屏。
- 顶部工具栏横向溢出，没有可折叠菜单。
- 建议移动端优先提供“查看 / 演示 / 评论”模式；平板再提供完整编辑。左右面板改为抽屉，顶部工具栏改为分组和溢出菜单。

证据：`audit-results/06-mobile-editor.png`

## 4. P0：必须先解决

### P0-1 恢复 CSS Token 解析

`flowchart-editor.css` 第一行直接从 `font-family` 开始，缺少 `@font-face {`。浏览器解析结果中没有 `:root` 规则，`--bg-base`、`--text-primary` 等变量为空。

修复后至少验证：

- 空白画布、模板弹窗、属性面板和设置弹窗均显示预期主题
- 所有内置模板的节点文字可读
- 深色和浅色背景上的文本、图标、连线、选中态满足对比度要求
- PNG/SVG/PDF 导出不继承错误的编辑器主题

### P0-2 增加视觉回归门禁

现有 51 个单元测试和语法检查均通过，但没有发现 CSS Token 完全失效。这说明测试覆盖了逻辑，没有覆盖真实视觉结果。

建议新增：

- CSS 解析测试：断言 `:root` 中核心变量存在
- 桌面截图：空白、模板弹窗、模板应用、节点选中、导出弹窗
- 移动截图：390px 和 768px
- 自动对比度检查：节点文字、工具栏、属性标签、状态提示
- DOM 可访问性检查：按钮名称、对话框语义、焦点顺序

## 5. P1：主编辑体验升级

### P1-1 重组顶部工具栏

保留高频命令：选择、连线、撤销、重做、自动布局、导出。

低频命令收入分组菜单：项目文件、Excel、更新、设置、清空、演示配置。增加命令面板（建议 `Ctrl/Cmd+K`）作为所有命令、页面、模板和节点的统一入口。

### P1-2 空白态与渐进式引导

空白画布显示：

- 从模板开始
- 导入 Excel / JSON / VSO
- 创建空白流程

首次拖拽、连线和导出只做一次轻提示，不常驻占用底部空间。

### P1-3 图形库升级

- 搜索图形和模板
- 分类折叠
- 最近使用、收藏
- 自定义图形包状态
- 拖拽预览和双击插入
- 键盘可操作

这部分应与既有 `DW-P2-02 Stencil Manager` 合并设计。

### P1-4 画布导航与复杂图管理

- 小地图 / Outline
- 适应全部、适应选区、100% 三种明确视图命令
- 节点搜索、查找替换、按角色/图层/标签筛选
- 网格、吸附、对齐、等距分布、参考线
- 折叠子流程和容器
- 大图按缩放级别减少次要文字

### P1-5 属性面板与上下文操作

- 内容、流程、外观、数据分组
- 多选批量编辑
- 节点旁浮动快捷栏
- 颜色色块增加名称和自定义输入
- 连线端口、路由、桥接和标签规则整合到单一面板

这部分应与既有 `DW-P2-03 Connection Rule Panel` 合并设计。

### P1-6 可访问性基础

- 所有图标按钮增加 `aria-label`
- 图形项、模板项和右键菜单改为语义化控件
- 所有对话框增加 `role="dialog"`、`aria-modal="true"`、标题关联和焦点锁定
- 关闭弹窗后焦点回到触发按钮
- 增加全局 `:focus-visible`
- 隐藏面板同步 `aria-hidden` 或从可访问树移除
- 支持 `prefers-reduced-motion`
- 键盘可创建、选择、移动、连接、编辑节点

## 6. P2：功能新增建议

### 已在现有工作单中规划

以下能力不应重复立项，应继续沿现有工作单实施：

- 导入预览与错误报告：`DW-P1-01`
- Excel/JSON 字段映射向导：`DW-P1-02`
- 模板中心：`DW-P2-01`
- 自定义图形包管理：`DW-P2-02`
- 连线路由规则面板：`DW-P2-03`
- 本地版本历史与回滚：`DW-P3-01`
- 真正的 Visio Bridge：`DW-P4-01`

### 建议新增到路线图

1. 流程质量检查器

   检测孤立节点、不可达节点、缺少开始/结束、断开的连线、重复编号、空标签、无出口判断、循环和跨页失效链接。问题可在画布上定位并一键修复部分规则。

2. 搜索、命令面板与小地图

   这是复杂图的基础设施，优先级应高于更多图形类型。

3. 交互式只读分享

   导出单文件 HTML 或本地只读 Viewer，保留页面、图层、标签、缩放、跨页链接和演示路径。它比直接做实时协作更符合当前本地优先架构。

4. 评论与审阅状态

   节点或连线可标记“待确认 / 已批准 / 需修改”，支持评论、负责人和解决状态。先做文件内审阅，再考虑多人实时同步。

5. Mermaid / BPMN 互操作

   支持 Mermaid 文本导入与再次编辑；BPMN 建议先做受控子集和校验，不要只增加一批外观相似的 BPMN 图形。

6. 流程分析增强

   在现有关键路径基础上增加瓶颈节点、角色负荷、最长等待、循环次数、SLA 风险和页面级摘要。

7. 平板编辑与移动查看

   手机优先保证查看、演示、搜索和评论；平板支持抽屉面板、触控端口、双指缩放和更大的点击目标。

8. 可选 AI 辅助

   文本生成流程、根据选中区域补全、解释流程、检测缺失步骤。必须明确哪些文本会发送到模型，并允许完全关闭；生成结果先进入预览，不直接覆盖画布。

## 7. 同类系统参考结论

| 系统 | 值得借鉴 | 对 DiagramWeave 的启示 |
|---|---|---|
| draw.io / diagrams.net | 多主题、页面、图层、标签、Outline、查找替换、可配置图形库、交互式导出、Mermaid | 优先补齐复杂图导航、搜索和只读分享，不只是增加图形数量 |
| Excalidraw | 命令面板、场景搜索、图形库、暗色模式、本地优先、协作、分享链接 | 统一命令入口和快速搜索能显著降低工具栏复杂度 |
| tldraw | 无限画布、触控/移动端、运行时扩展、多人同步、AI 画布原语 | 扩展内核方向正确，但 UI 扩展点和移动交互也要成为正式能力 |
| bpmn-js | 标准 BPMN 模型、可扩展建模器、导入导出与校验 | BPMN 应作为语义模型和校验能力，不应只做形状包 |
| React Flow / xyflow | MiniMap、Controls、Background 等标准节点编辑器组件 | 小地图、视图控制和节点工作流应成为默认编辑器基础设施 |
| yFiles / yEd Live | 自动布局选择、Overview、图分析、触控、层级细节、复杂连线路由 | DiagramWeave 可将“自动布局 + 关键路径”发展成流程工程差异化能力 |

## 8. 建议实施顺序

### 阶段 A：稳定视觉基础

1. 修复 CSS 解析和主题变量。
2. 修复所有模板节点的文字/填充对比度。
3. 增加桌面、移动和主题截图回归。
4. 增加基础可访问性门禁。

### 阶段 B：重构主工作流

1. 空白态和项目入口。
2. 工具栏分组与命令面板。
3. 图形库搜索、折叠和收藏。
4. 小地图、搜索和复杂图导航。
5. 属性面板分组、多选和上下文工具栏。
6. 手机查看模式和平板编辑布局。

### 阶段 C：完成现有工作单

1. 导入预览与映射向导。
2. 模板中心、图形包和连线规则。
3. 版本历史。
4. Visio Bridge。

### 阶段 D：形成产品差异化

1. 流程质量检查器。
2. 流程分析增强。
3. 交互式只读分享与审阅。
4. Mermaid/BPMN 互操作。
5. 可选 AI 辅助。

## 9. 验证结果与限制

- `npm.cmd test`：11 个测试文件、51 个测试通过。
- `npm.cmd run typecheck`：通过。
- 自动测试通过不能代表 UI 正常；当前 CSS Token 失效正说明需要浏览器级视觉回归。
- 本次视觉审查基于当前本地代码和当前运行状态。
- 屏幕截图只能证明可见问题；完整 WCAG 结论仍需键盘、读屏器、缩放和颜色对比度工具测试。
